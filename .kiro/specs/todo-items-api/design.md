# Design Document: TodoItems API

## Overview

The TodoItems API is a RESTful web service built with ASP.NET Core 9.0 that provides CRUD operations for managing todo items. The API follows standard REST conventions, uses Entity Framework Core with an in-memory database for data persistence, and includes OpenAPI/Swagger documentation for API exploration and testing.

### Key Design Goals

- Simple, RESTful API design following HTTP conventions
- Lightweight in-memory data storage suitable for development and testing
- Comprehensive API documentation through OpenAPI/Swagger
- Proper HTTP status codes and error handling
- Dependency injection for testability and maintainability

### Technology Stack

- **Framework**: ASP.NET Core 9.0
- **ORM**: Entity Framework Core 9.0
- **Database**: EF Core InMemory Provider
- **API Documentation**: Microsoft.AspNetCore.OpenApi with Swagger UI
- **Language**: C# with nullable reference types enabled

## Architecture

### Architectural Pattern

The API follows a layered architecture with clear separation of concerns:

```
┌─────────────────────────────────────┐
│         HTTP Clients                │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│      TodoItemsController            │
│   (API/Presentation Layer)          │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│      TodoContext (DbContext)        │
│      (Data Access Layer)            │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│    InMemory Database Provider       │
│      (Data Storage)                 │
└─────────────────────────────────────┘
```

### Design Rationale

1. **Controller-Based API**: Using ASP.NET Core MVC controllers provides attribute routing, model binding, and built-in validation support.

2. **Direct DbContext Access**: For this simple CRUD API, the controller directly accesses the DbContext. This avoids over-engineering with repository patterns while maintaining testability through dependency injection.

3. **InMemory Database**: Suitable for development, testing, and demonstration purposes. Can be easily swapped for a persistent database provider (SQL Server, PostgreSQL, etc.) by changing the DbContext configuration.

4. **Async/Await Pattern**: All database operations use async methods to improve scalability and responsiveness.

## Components and Interfaces

### TodoItem Model

The core domain entity representing a todo task.

```csharp
public class TodoItem
{
    public long Id { get; set; }
    public string? Name { get; set; }
    public bool IsComplete { get; set; }
}
```

**Properties**:
- `Id`: Primary key, auto-generated by the database
- `Name`: Task description (nullable to handle incomplete data)
- `IsComplete`: Boolean flag indicating task completion status

### TodoContext (DbContext)

Entity Framework Core database context for managing TodoItem entities.

```csharp
public class TodoContext : DbContext
{
    public TodoContext(DbContextOptions<TodoContext> options)
        : base(options)
    {
    }

    public DbSet<TodoItem> TodoItems { get; set; } = null!;
}
```

**Responsibilities**:
- Define the TodoItems DbSet for querying and saving entities
- Configure entity mappings (uses conventions for this simple model)
- Manage database connections and transactions

### TodoItemsController

API controller exposing RESTful endpoints for TodoItem operations.

```csharp
[Route("api/[controller]")]
[ApiController]
public class TodoItemsController : ControllerBase
{
    private readonly TodoContext _context;

    public TodoItemsController(TodoContext context)
    {
        _context = context;
    }

    // GET: api/TodoItems
    [HttpGet]
    public async Task<ActionResult<IEnumerable<TodoItem>>> GetTodoItems()

    // GET: api/TodoItems/5
    [HttpGet("{id}")]
    public async Task<ActionResult<TodoItem>> GetTodoItem(long id)

    // POST: api/TodoItems
    [HttpPost]
    public async Task<ActionResult<TodoItem>> PostTodoItem(TodoItem todoItem)

    // PUT: api/TodoItems/5
    [HttpPut("{id}")]
    public async Task<IActionResult> PutTodoItem(long id, TodoItem todoItem)

    // DELETE: api/TodoItems/5
    [HttpDelete("{id}")]
    public async Task<IActionResult> DeleteTodoItem(long id)
}
```

**Endpoints**:

| Method | Route | Description | Success Status |
|--------|-------|-------------|----------------|
| GET | /api/todoitems | Retrieve all todo items | 200 OK |
| GET | /api/todoitems/{id} | Retrieve specific todo item | 200 OK |
| POST | /api/todoitems | Create new todo item | 201 Created |
| PUT | /api/todoitems/{id} | Update existing todo item | 204 No Content |
| DELETE | /api/todoitems/{id} | Delete todo item | 204 No Content |

### Program.cs Configuration

Application startup and middleware configuration.

**Service Registration**:
```csharp
builder.Services.AddControllers();
builder.Services.AddDbContext<TodoContext>(opt =>
    opt.UseInMemoryDatabase("TodoList"));
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
```

**Middleware Pipeline**:
```csharp
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.UseCors();
app.UseAuthorization();
app.MapControllers();
```

## Data Models

### TodoItem Entity

**Schema**:
```
TodoItem
├── Id: long (Primary Key, Auto-increment)
├── Name: string? (Nullable)
└── IsComplete: bool (Default: false)
```

**Validation Rules**:
- `Id`: Generated by database, must be unique
- `Name`: Optional field, no length constraints in this version
- `IsComplete`: Required boolean, defaults to false

**JSON Representation**:
```json
{
  "id": 1,
  "name": "Walk the dog",
  "isComplete": false
}
```

### Database Context

**InMemory Database Configuration**:
- Database Name: "TodoList"
- Provider: Microsoft.EntityFrameworkCore.InMemory
- Lifetime: Scoped (per HTTP request)
- Data Persistence: In-memory only (data lost on application restart)

**Entity Configuration**:
- Uses EF Core conventions for table and column naming
- Primary key auto-detected from `Id` property
- No explicit indexes or constraints needed for in-memory provider
